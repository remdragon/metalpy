lowering:
	CFG:
		metalpy needs a CFG so that it can know when to emit incref/decref IR ops.
		Therefore it needs to track the status of RC variables as they pass through
		a function.
		when a variable is created, it is starts off with a status OWNED.
		A parameter (with no ownership annotations) in a function starts off
			with a status of BORROWED. this is because by default we do not
			incref parameters passed to a function, and the receiving function
			doesn't decref borrowed parameters.
		It's possible to transfer ownership of a reference to a function.
			This is done on parameters using a handshake:
				<code>
				def foo( move[str] s ) -> None:
					...
				foo( move( s ))
				</code>
				Notice that both the function definition and the callsite must agree that the variable is being moved
			This is done on self with @move:
				<code>
				class Foo:
					@move
					def release( self ) -> Result[Ptr[u8],OwnershipError.SharedReference[Foo]]:
						...
				</code>
			Both mechanisms above transition the variable's state to MOVED.
			Any attempt to reference a variable in a MOVED state is a compile error.
			A MOVED variable doesn't need a DECREF.
			P.S. I really wish there was a way to apply the move() requirement to
			a self parameter too, but I can't find a clean clear unambiguous syntax.
				This doesn't work because it looks like we're moving self before calling release()
					move(self).release()
				this doesn't work because it looks like we're moving the function
					move(self.release)()
				this doesn't work because it looks like a type specification:
					self[move].release()
		Sometimes you explicitly want to make sure a parameter gets incref/decref treatment.
		One anticipated need for this is threading, though I haven't spec'd that yet.
			This only needs to be indicated on the function parameter:
				<code>
				def foo( copy[str] s ) -> None:
					...
				foo( s )
			A parameter declared copy[T] starts off with a state of COPY
				I'm not sure we need to distinguish between COPY and OWNED.
				we can experiment with dropping the COPY state.
		unnamed temporary variables created by an expression need to be DECREF
			when the expression falls out of scope.
			This needs to happen at the same time that ir.DeleteTemp() is emitted.
			deleted variables can be assigned a state of MOVED.
			we can experiment with removing the variables out of the CFG state if
				that doesn't created a problem with state consistency.
		when a variable is done, it will have a state of either OWNED, BORROWED, COPY, or MOVED.
			only OWNED/COPY need a DECREF.
			BORROWED variable reference is held by the calling function
			MOVED variable has either had its reference ownership sent somewhere else,
				or it was already DECREF'd.
		The critical piece of functionality needed by the CFG is to make sure
			that INCREF/DECREF gets emitted exactly where needed and to generate
			a compile error if thats not possible.
		anonymous unions:
			anonymous unions must INCREF/DECREF as appropriate. This means that
			it may be necessary to emit a typecheck.
			<code>
			def foo( x: copy[str|i32] ):
				# function prologue IR pseudo-code:
				if x.tag == _u_i32_str.TAG_str:
					INCREF(x.v_str)
				# function epilogue IR pseudo-code:
				if x.tag == _u_i32_str.TAG_str:
					DECREF(x.v_str)
			</code>
			# NOTE that all RC objects have the same header:
			<code>
			def foo( x: str|int ):
				# function prologue IR pseudo-code:
				INCREF(x.v_int) # no if needed because all members of Union[int,str] are RC
				# function epilogue IR pseudo-code:
				DECREF(x.v_int) # same reasoning
		Some examples:
			<code>
			def takeown( x: move[T] ):
				pass
			
			def foo1( s: move[str] ):
				if 'foo' in s:
					takeown( s ) # transition s from OWNED to MOVED
				# <<< compile error - s is in an indeterminate state after the if
				# the true branch transitions s from OWNED to MOVED
				# but the else branch leaves it in OWNED
				print( s )
			
			def foo2( s: str ):
				takeown( s ) # compile error - cannot move(T) a BORROWED reference
			
			# this next example illustrates that the CFG might have to make 2 passes
			# on loop bodies, to make sure ownership isn't violated like the following
			# example definitely would because s is the same object in the 2nd pass
			def foo3( s: copy[str] ):
				# NOTE: s gets INCREF in function prologue - not at call-site
				while 'foo' in s:
					takeown( s ) # compile error - cannot move(T) a possibly MOVED reference
			
			# the following example shouldn't be a problem because s2 is a different
			variable in each pass of the loop:
			def foo4( s: str ):
				for s2 in s.split( ',' ):
					takeown( s2 )
			
			def foo5( s: str ): # s=BORROWED
				s2 = s # s2 is a copy of s, so s=BORROWED, s2=OWNED or COPY. IR( ASSIGN(s2,s); INCREF(s2) )

				# epilogue:
				DECREF(s2)
			</code>

		The CFG will need to track unions as Union|UnionView

		class TaggedUnion( Type ):
			...
			def view_is_type( self, type: Type ) -> UnionView|None:
				leaves = self.leaves()
				if type not in leaves:
					raise CompilationError( f"redundant type check, {type!r} can't be in {leaves!r}" )
				return UnionView( union = self, types = set([ type ]))

			def view_not_type( self, type: Type ) -> UnionView|None:
				leaves = self.leaves()
				if type not in leaves:
					raise CompilationError( f"redundant type check, {type!r} can't be in {leaves!r}" )
				leaves.remove( type )
				return UnionView(
					union = self,
					types = leaves,
				)

		class UnionView( Type ):
			union: TaggedUnion
			leaves: set[Type]

			def view_is_type( self, type: Type ) -> UnionView|None:
				if type not in self.leaves:
					raise CompilationError( f"redundant type check, {type!r} can't be in {leaves!r}" )
				return UnionView( union = self.union, leaves = set([ type ]))

			def view_not_type( self, type: Type ) -> UnionView|None:
				if type not in self.leaves:
					raise CompilationError( f"redundant type check, {type!r} can't be in {leaves!r}" )
				new_leaves = self.leaves.clone()
				new_leaves.remove( type )
				return UnionView( self.union, new_leaves )

		def foo( x: int|str|bytes ) -> None:

			elif x is str: # UnionView( union = int|str|None, leaves = [ str, bytes ]).view_is_type(str) -> UnionView( union = int|str|bytes, leaves = [ str ])
				print( x ) # translates to print( x.v_str )
			# the false branch of the elif above triggers type translation: x`` = UnionView(...).view_not_type(str)
			else: # at this point we have a single-type UnionView
				print( x ) # translates to print( x.v_bytes )

			# at this point, we've exited the if-else-chain, the UnionView is discarded and x is int|str|bytes again

			# the next example is a wrinkle on the above logic.

			if x is int:

	opportunistic union emission
		when a union is used, we need to generate IR to reach through it to the
			underlying code.
		note that we disambiguate directly in generated code when doing things directly
		with the union, but if we call a method on a union object, we attempt to auto-generate
		a method that does the disambigutation for us. If the method isn't available on all types
		or has incompatible function signatures, it will be caught when it gets resolved and lowered,
		so we don't have to do any special type checking when actually generating the automatic
		union methods

		For this code example, assume:
			@union
			class IntStr:
				v_int: int
				v_str: str
		
		P.S. this is *not* a specification for how to name automatic unions in C, that is not
			in scope for the lowering stage.
		P.P.S. through the examples below, I use TAG_INT and TAG_STR, this is not a specification,
			just a placeholder for the actual values that will be generated to represent each member

		this:
			a: IntStr = 'foo'
		becomes:
			a = IntStr.v_str( 'foo' )
		this:
			if isinstance( a, int ):
				print( a )
		becomes:
			if a.tag == IntStr.TAG_INT:
				print( a.v_int )
		this:
			print( a )
		becomes:
			print( a.__str__() )
		and auto-generates the following wrapper if it doesn't already exist:
			class IntStr:
				def __str__( self ) -> str:
					match self.tag:
						case IntStr.TAG_INT:
							return self.v_int.__str__()
						case IntStr.TAG_STR:
							return self.v_str.__str__()
						case _:
							sys.panic( 'system invariant, invalid union tag' )

	slice[T] (builtins/__init__.py) is a borrowed view (_ptr/__len only, no
		owning storage) - any function that snapshots a slice's .len() once
		and then indexes it across multiple statements (e.g. str.concat's
		two `for i in range(count): part = parts.get_unchecked(i)` loops)
		is reading through a pointer that another thread could be mutating
		or freeing concurrently, even though get_unchecked's own bound
		(i < count) can never itself be violated. Fixing this for real needs
		either an owned-copy path (slice[T].clone() -> list[T], or similar -
		but slice has no allocator/capacity of its own to build that from,
		and list[T] has no constructor that takes a slice/iterable either)
		or real ownership/borrow tracking that proves the slice can't be
		mutated for the duration of the call - this is really the same
		unsolved problem as incref/decref/move[T] above, not a one-off bug
		in str.concat specifically
