		_lower_stmt's own per-statement DeleteTemp loop decrefs whatever's
		still registered when a temp's expression-scoped lifetime ends -
		covers every Call/Allocate site at once rather than needing each
		hunted down individually; field_value() also untracks a fresh
		temp embedded into a field, mirroring assign()'s same discipline).
		RCClass attribute lifetime / __init__ construction (see RCCLASS
		ATTRIBUTE LIFETIME.md and the approved plan) is also implemented,
		scoped to non-subclassed RCClasses:
		- ClassName(...) for a class declaring __init__ now actually works
			(previously always "not callable" - _try_lower_construct_call
			just bailed). Allocates self uninitialized, calls __init__ with
			its own parameter list (not the field=value sugar), wraps the
			result in Result[Foo,E] when __init__ is fallible
			(Result[None,E]), drops self's own refcount (not __del__) on
			Err - matches SYNTAX.md's own spec exactly.
		- each attribute is tracked via cfg.attr_assign() - a thin extension
			of assign()'s own fresh/replace logic, keyed by a 'self.'-
			prefixed name so it can never collide with a same-named local
			parameter (def __init__(self, a): self.a = a). Unlike locals,
			every attribute is tracked regardless of RC-ness (definite-
			assignment matters even for a plain `a: int`), and
			complete_construction() (called on every success-path return -
			AST-shape Result.Ok(...)/Result.Err(...) recognition, same
			spirit as defer/errdefer's own textual recognition, decides
			success vs failure for a fallible __init__) requires every
			attribute present, then cancels their entries WITHOUT decref
			(ownership transfers into the now-complete self, mirroring
			move()'s cancel mechanism) before the ordinary return_() unwind
			runs. A fallible __init__'s Err path skips this - incomplete
			state is expected there, and the ordinary unwind correctly
			decrefs whichever attributes were actually set.
		- self cannot be used as a Call receiver/argument, Assign src,
			Return value, Allocate field value, or SetItem value until every
			attribute is initialized (self.attr - GetAttr/SetAttr.obj - is
			the one exception) - release builds don't zero memory (see
			sys.alloc's debug-only zeroing), so a method reading an
			uninitialized field would be genuine garbage, not just logically
			wrong. Enforced centrally in _emit(), same technique as
			fresh_temp()'s own registration.
		- default attribute values (already-existing Variable.init, both
			AnnAssign and bare Assign forms) get an unconditional prologue
			assignment before __init__'s own body runs, lowered in the
			class's own scope (self isn't in scope for a default
			expression, matching Python's own class-body semantics) -
			also fixed _lower_allocate_fields's own "missing field(s)"
			check to fall back to a default there too, for the plain
			__allocate__()/no-__init__ construction path.
		- ordinary (non-__init__) SetAttr on an already-constructed
			instance is "always a replace" (RCCLASS ATTRIBUTE LIFETIME.md) -
			cfg.attr_replace(), reading the field's current value fresh via
			GetAttr (field CONTENTS still aren't tracked across statements,
			see below) since there's no tracked binding to consult. This is
			the concrete resolution of the "SetAttr storing an RC value
			into an existing field isn't tracked" half of the gap noted
			below - SetItem and a struct's own teardown remain open.
		- found and fixed a real, pre-existing, unrelated bug along the way
			(confirmed via a clean-checkout repro): _lower_allocate_fields's
			"every field required" check doesn't apply to a CUnion (only
			ONE member is ever meaningfully set - ResultPayload(ok=val)
			never gives err) - Result.Ok/Result.Err's own bodies had never
			actually been exercised through a full Compiler.run() before,
			so this went unnoticed until __init__'s own fallible-
			construction path became the first thing to do so.

		part of this: remodel move[T]/Move properly. It's currently a Type
		wrapper (mpy_types.Move, holding .inner), which is wrong - move[T]
		is an ownership status (OWNED vs BORROWED) on a binding, not a

	additional NoReturn semantics:
		previously I stated NoReturn is just a None with a flag for the emitter.
		I was incorrect.
		
		A return statement in a NoReturn function should be a compile error:
		
			def die() -> NoReturn
				return
		
		Additionally, we need dead code detection. The following print statement
		is unreachable because die() is NoReturn. It should be a compile error,
		but I'm guessing this will be dependent on the CFG being implemented first:
		
			def foo() -> None:
				die()
				print( 'hello' )

	union disambiguation:
		unions need to have a lowering wrapper to represent the currently understood type.

		P.S. Shouldn't TaggedUnion.leaves() cache its results?

		The CFG will need to track unions as Union|UnionView

		class TaggedUnion( Type ):
			...
			def view_is_type( self, type: Type ) -> UnionView|None:
				leaves = self.leaves()
				if type not in leaves:
					raise CompilationError( f"redundant type check, {type!r} can't be in {leaves!r}" )
				return UnionView( union = self, types = set([ type ]))

			def view_not_type( self, type: Type ) -> UnionView|None:
				leaves = self.leaves()
				if type not in leaves:
					raise CompilationError( f"redundant type check, {type!r} can't be in {leaves!r}" )
				leaves.remove( type )
				return UnionView(
					union = self,
					types = leaves,
				)

		class UnionView( Type ):
			union: TaggedUnion
			leaves: set[Type]

			def view_is_type( self, type: Type ) -> UnionView|None:
				if type not in self.leaves:
					raise CompilationError( f"redundant type check, {type!r} can't be in {leaves!r}" )
				return UnionView( union = self.union, leaves = set([ type ]))

			def view_not_type( self, type: Type ) -> UnionView|None:
				if type not in self.leaves:
					raise CompilationError( f"redundant type check, {type!r} can't be in {leaves!r}" )
				new_leaves = self.leaves.clone()
				new_leaves.remove( type )
				return UnionView( self.union, new_leaves )
		
		this structure will allow the CFG to track the currently understand type of a tagged union
		as it passes through a match or ifelse tree

		def foo( x: int|str|bytes ) -> None:
			if x is int: # (int|str|bytes).view_is_type(int) -> UnionView( union = int|str|bytes, leaves = [ int ])
				print( x ) # translates to print( x.v_int )
			# the false branch of the if above triggers type translation: x` = (int|str|bytes).view_not_type(int) -> UnionView( union = int|str|bytes, leaves = [ str, bytes ])
			elif x is str: # UnionView( union = int|str|None, leaves = [ str, bytes ]).view_is_type(str) -> UnionView( union = int|str|bytes, leaves = [ str ])
				print( x ) # translates to print( x.v_str )
			# the false branch of the elif above triggers type translation: x`` = UnionView(...).view_not_type(str)
			else: # at this point we have a single-type UnionView
				print( x ) # translates to print( x.v_bytes )

			# at this point, we've exited the if-else-chain, the UnionView is discarded and x is int|str|bytes again

			# the next example is a wrinkle on the above logic.

			if x is int:
				return
				# because this branch of the if can't fall out,
				# x's type is permanently UnionView.view_not_type(int) for the rest of the function
			elif x is str:
				print( x )
				# this branch falls out of the if, so it doesn't permanently modify x's type
			else:
				print( x )
				# this branch also falls out of the if, so it doesn't modify x's type

			# here outside the if, x is now permanently UnionView( union = int|str|bytes, leaves = [ str, bytes ])
			# for the rest of this function

			if x is int: # this is a compilation error, because the current UnionView already excludes int
				...

			implementation thoughts...
			while the CFG is stepping through an IF or MATCH, it needs to calculate a variable's state transitions.
			For example, when testing an if condition that is a type check:
				true_type = X.view_is_type( TYPE )

				exit_type = X

			then, if its discovered the if body can't fall out, exit_type = else_type

			def foo( x: int|None ) -> None:
				if x is int and x < 4: # this is okay because in the 2nd half of the "and", x is UnionView( ..., leaves = [ int ])
					...

	opportunistic union emission
		when a union is used, we need to generate IR to reach through it to the
			underlying code.
		note that we disambiguate directly in generated code when doing things directly
		with the union, but if we call a method on a union object, we attempt to auto-generate
		a method that does the disambigutation for us. If the method isn't available on all types
		or has incompatible function signatures, it will be caught when it gets resolved and lowered,
		so we don't have to do any special type checking when actually generating the automatic
		union methods

		For this code example, assume:
			@union
			class IntStr:
				v_int: int
				v_str: str
		
		P.S. this is *not* a specification for how to name automatic unions in C, that is not
			in scope for the lowering stage.
		P.P.S. through the examples below, I use TAG_INT and TAG_STR, this is not a specification,
			just a placeholder for the actual values that will be generated to represent each member

		this:
			a: IntStr = 'foo'
		becomes:
			a = IntStr.v_str( 'foo' )
		this:
			if isinstance( a, int ):
				print( a )
		becomes:
			if a.tag == IntStr.TAG_INT:
				print( a.v_int )
		this:
			print( a )
		becomes:
			print( a.__str__() )
		and auto-generates the following wrapper if it doesn't already exist:
			class IntStr:
				def __str__( self ) -> str:
					match self.tag:
						case IntStr.TAG_INT:
							return self.v_int.__str__()
						case IntStr.TAG_STR:
							return self.v_str.__str__()
						case _:
							sys.panic( 'system invariant, invalid union tag' )
