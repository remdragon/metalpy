This is my proposal for building the C emitter. Since we already had this working
pretty well in my previous attempt to build this compiler, I will be relying
heavily on concepts that exist there.

The function of this module (emitter_c.py) is to take the IR generated by
lowering.py and convert it into C source code. Linking to an actual executable
is not in scope for this file.

NOTE that my design is aggressively trying to avoid dependency on the C runtime
for windows builds unless user code creates a dependency on it themselves.
but I am going to do everything possible to avoid creating a dependency on it
from metalpy's stdlib.

Avoiding the C runtime is more of a linking concern (not in scope here). I
am mentioning it here only because we want to avoid including any headers
that would create a requirement to link against msvcrt on Windows.

The target specification is C11. It's widely available and has some important
enhancements that will make this easier.

Here is the C prologue the previous version was using:

```
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdatomic.h>

// __del__ can run on any thread the moment a refcount hits 0 - retain/release must
// therefore be real atomic RMW ops, not plain ++/-- (a data race under
// concurrent use, silently wrong under optimization even single-threaded).
//
// METALPY_IMMORTAL_REFCOUNT marks statically-baked objects that must never
// actually be freed. retain/release both skip touching the counter entirely
// for these, rather than just starting it at a "big enough" value:
// a long-running, loop-heavy program can genuinely drive
// billions of incref/decref pairs against the same shared literal over its
// lifetime, and a plain sentinel value would eventually be decremented to 0
// for real.
#define METALPY_IMMORTAL_REFCOUNT INT32_MAX

typedef struct {
	_Atomic int32_t ref_count;
} ObjectHeader;

static inline void retain_object( ObjectHeader* obj ) {
	if ( obj && obj->ref_count != METALPY_IMMORTAL_REFCOUNT ) {
		atomic_fetch_add( &obj->ref_count, 1 );
	}
}

static inline void release_object( ObjectHeader* obj, void (*destructor)(void*) ) {
	if ( obj && obj->ref_count != METALPY_IMMORTAL_REFCOUNT ) {
		// atomic_fetch_sub returns the PRE-decrement value; ==1 means this
		// decrement just brought it to 0.
		if ( atomic_fetch_sub( &obj->ref_count, 1 ) == 1 ) {
			if ( destructor ) {
				destructor( obj );
			}
		}
	}
}
```

When generating C names for objects, lets attempt the following:
	
	for normal objects, take the qualname and replace . with $
		builtins.str -> builtins$str
	
	for anonymous unions, we need to create a name that's completely unique.
	start with a $__u, replace the | with $$__u$ and then replace . with $
		builtins.str|builtins.str -> $__u$$builtins$str$$builtins$int
		(even if a user creates a __u module in their code, it wouldn't have the $ prefix in the cname)
		(even if we create other anonymous objects in the future, they won't start with __u)

I'm not sure what else needs to be specified here. The IR ops are pretty well
defined and translation to C should be pretty straight-forward.
